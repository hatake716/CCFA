CCFA プライバシーポリシー

発効日: 2026年8月27日 ・ 対象アプリ: CCFA（日本語入力対応Linuxコンテナ、パッケージ名 io.github.hatake716.ccfa）
本ページの固定URL: https://hatake716.github.io/CCFA/privacy.html

要点: CCFAは、解析（アナリティクス）・広告・テレメトリー・アカウント・クラウド同期のサーバーを一切運用していません。CCFAが個人データを収集・送信・販売・第三者提供することはありません。

アプリがローカルで扱うデータ

  • アプリ専用領域（Context.filesDir）内のLinuxコンテナのファイルと /workspace。
  • アプリ内ターミナル（PTY）の動作に必要なローカルの入出力。
  • ストレージ共有設定でユーザーがシステムのフォルダ選択画面（Storage Access Framework, ACTION_OPEN_DOCUMENT_TREE）から明示的に選択したAndroid側フォルダ。ユーザーがフォルダを選択するまで、いかなるAndroid側フォルダも共有されません。付与したフォルダ権限は、設定の無効化・削除によりいつでも取り消せます。

選択したフォルダがLinuxコンテナへ直接マウントされることはありません。ユーザーが同期を実行したときにのみ、選択フォルダとアプリ専用領域内の /workspace/phone/<名前> との間で内容がミラーコピーされます（設定に応じて双方向・取込のみ・書出のみ）。共有設定が有効な間、コンテナ内のプログラムは /workspace にコピー済みの内容を読み取れます。

CCFAが無関係なAndroidストレージを走査することはありません。Google Play版が要求する権限は INTERNET のみで、広範なストレージ権限は保持しません。

CCFAが行うネットワークアクセス

CCFAのネットワークアクセスは、ユーザーの操作で開始されるLinux環境構築のためだけに使われます。具体的には、Linux Baseイメージを提供元（Canonicalの cdimage.ubuntu.com）からダウンロードすること、およびユーザーが指示した通常のLinuxパッケージのインストール（例: apt。設定されたパッケージミラーと直接通信します）です。

CCFAが、プロプライエタリなサードパーティ製AI CLIを自動的にダウンロード・インストール・修復・ログイン・認証することはありません。サードパーティ提供者のOAuthトークン・APIキー・サブスクリプション資格情報・アカウント権限・レート制限を取得したり中継したりすることもありません。

ユーザーがインストールするサードパーティソフトウェア

ユーザーがCCFAのLinux環境内にサードパーティ製AI CLIその他のネットワークを利用するプログラムを手動でインストールした場合、そのソフトウェアは自身の提供元や他のサービスと直接通信することがあります。

その通信は、当該サードパーティの利用規約・プライバシーポリシー・アカウント設定・データ保持の選択・提供地域ポリシーその他の適用条件に従います。CCFAがこのサードパーティ通信を処理することはありません。

ローカルの認証情報

ユーザーがコンテナ内に手動でインストールしたソフトウェアが作成・保存する認証情報は、そのソフトウェア自身が送信・書き出しをしない限り、アプリ専用のLinuxファイルシステム内に留まります。CCFAがそれらの認証情報を意図的に閲覧・アップロード・販売・仲介することはありません。

データの削除

  • Linuxコンテナを削除すると、そのコンテナのrootfsが削除されます。
  • /workspace（/workspace/phone/ のミラーコピーを含む）はアプリ専用領域にあり、アプリのアンインストールで削除されます。
  • 共有用に選択したAndroid側フォルダのファイルはアプリの外にあり、ユーザーの管理下に残ります。CCFAがそれらを変更するのは、書き込み方向を含む同期をユーザーが実行したときだけです。

子どもについて

CCFAは、子どもを含むいかなる利用者からも個人データを収集しません。

配布チャネルによる違い

本ポリシーはGoogle Play版（パッケージ名 io.github.hatake716.ccfa）の動作を説明しています。別途配布されるサイドロード版（GitHub Releases、歴史的パッケージ名 io.github.hatake716.claudecodeandroid）は1点だけ異なり、Androidの全ファイルアクセス権限を使用して、ユーザーが設定したAndroidフォルダをSAFミラー同期ではなくLinuxコンテナへ直接バインドマウントします。追加のデータ収集はありません。

CCFA privacy disclosure (English)

Effective date: 2026-08-27 · Application: CCFA (package io.github.hatake716.ccfa)

CCFA itself does not operate an analytics, telemetry, advertising, account, or cloud-sync server. CCFA does not collect, transmit, sell, or share personal data with the developer or any third party.

Data CCFA accesses locally

  • App-private Linux container files and /workspace (both inside the app-private storage area, Context.filesDir).
  • Local terminal input/output needed to operate the in-app PTY.
  • Android folders that the user explicitly selects with the system folder picker (Storage Access Framework, ACTION_OPEN_DOCUMENT_TREE). No Android folder is shared until the user selects one; the persisted folder permission can be revoked by the user at any time by disabling or removing the mapping.

Selected folders are not mounted into the Linux container. Instead, when the user runs a sync, their contents are mirror-copied between the selected Android folder and /workspace/phone/<name> inside the app-private area (bidirectional, import-only, or export-only, as configured). Programs inside the Linux container can read whatever has been copied into /workspace while the mapping is enabled.

CCFA does not scan unrelated Android storage. It holds no broad storage permission: the Google Play build requests only INTERNET.

Network access performed by CCFA

CCFA uses network access only for Linux-environment setup started by the user: downloading the Linux Base image from its upstream provider (Canonical's cdimage.ubuntu.com) and installing ordinary Linux packages the user requests (for example via apt, which contacts the configured package mirrors directly).

CCFA does not automatically download, install, repair, log in to, or authenticate a proprietary third-party AI CLI. It does not obtain or proxy a third-party provider's OAuth token, API key, subscription credential, account entitlement, or rate limit.

Third-party software installed by the user

If the user manually installs a third-party AI CLI or other networked program inside the CCFA Linux environment, that software may communicate directly with its own provider or other services. Such traffic is governed by that third party's terms, privacy policy, account settings, data-retention choices, supported-region policy, and other applicable conditions. CCFA does not claim that this third-party traffic is processed by CCFA.

Local credentials

Credentials created or stored by software that the user manually installs inside the Linux container remain inside the app-private Linux filesystem unless that software itself transmits, exports, or writes them elsewhere. CCFA does not intentionally inspect, upload, sell, or broker those credentials.

Data deletion

  • Removing a Linux container deletes that container rootfs.
  • /workspace (including /workspace/phone/ mirror copies) is app-private and is deleted when the app is uninstalled.
  • Files in the Android folders the user selected for sharing live outside the app and remain under the user's control; CCFA only changes them when the user runs a sync whose direction writes to them.

Children

CCFA does not collect personal data from any user, including children.

Distribution channels

This policy describes the Google Play build (package io.github.hatake716.ccfa). The separately distributed sideload build (GitHub Releases, historical package io.github.hatake716.claudecodeandroid) differs in one respect: it uses Android's all-files-access permission and binds user-configured Android folders directly into the Linux container instead of SAF mirror sync. It performs no additional data collection.
